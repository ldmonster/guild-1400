## FIXED

### FIX-1 (BUG, behavioral) — save_world_write.cpp `SaveWriteGameStateSection`
gilde.exe 0x5a4938 (VIBE_Save_WriteGameStateHeader), live-slot scan @0x5a4980-0x5a4985.

DISASM (reference of record):
  loc_5A4972: cmp word_12CE910[eax], 0FFFFh
  loc_5A4980: add eax, 218h          ; stride = 0x218 = 536 bytes
              cmp eax, 64800h        ; terminate at 0x64800 = 411648 bytes
              jnz loc_5A4972         ; => 411648 / 536 == 768 person records

The shared constant `io::kPersScanBytes` (save_person.h, OUTSIDE this chunk) carries
the Hex-Rays *word-scaled* artifact 205824 (Hex-Rays typed word_12CE910 as __int16[],
so its "v2 += 268 / v2 != 205824" is half the byte values). 205824/536 == 384, so
both loops in SaveWriteGameStateSection (the live-count loop and the per-record write
loop) iterated only 384 of 768 records — dropping the back half of the person table.

Before: `for (o=0; o != kPersScanBytes(205824); o += kPersStride(536))`  -> 384 iters
After : `for (o=0; o != kPersScanBytesExact(411648); o += kPersStride(536))` -> 768 iters

Evidence the 411648 value is correct (and that 205824 is the lone outlier): every
other person-array walk in the tree uses 411648 / 0x64800 / "536 * 768"
(person_record.h kPersonScanBound=411648; save_world_tables_save_recon.h
kSwt_PersonSpan=0x64800; ai_meister_*, location3, groundplan_recon, he_entity_query,
session_select, etc.). kPersScanBytes(205824) lives only in save_person.h.

Fix kept inside the chunk: added a file-local `kPersScanBytesExact = 411648` in
save_world_write.cpp (cited to the disasm) rather than editing save_person.h (another
chunk's file). Note: io::kPersScanBytes is ALSO consumed by save_person.cpp's preamble
and play/session_save.cpp with the same 2x undercount — those belong to other chunks;
flagged here for the save_person / session owners to correct the shared constant to
411648 at the source.

### FIX-2 (comment accuracy) — worldio.cpp `WorldIoSceneTagValid`
